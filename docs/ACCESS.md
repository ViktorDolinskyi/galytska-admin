# Користувачі, ролі та права доступу (Admin GS)

Де: **Налаштування → Користувачі та доступ**. Розділ видно тим, у кого право «Користувачі та доступ» ≥ Перегляд.

## Як це працює

```
Користувач (email + пароль, Supabase Auth)
   └─ роль ── рівень доступу до кожного розділу
   └─ індивідуальні права (необов'язково) ── перекривають роль для окремих розділів
```

**Рівні доступу** до розділу:

| Рівень | Що можна |
|---|---|
| Немає | розділ прихований у меню, дані з бази не віддаються |
| Перегляд | лише читання: кнопки додавання, збереження й видалення сховані |
| Редагування | додавати й змінювати |
| Повний | усе, включно з видаленням |

**Розділи**: Панель, Процеси, Матриці, Цілі, Компанія, Звіти, Аналітика, Бюджет, Розвиток,
Будь в темі, Налаштування (довідники, система), Користувачі та доступ.
«Зовнішній вигляд» і «Профіль» у Налаштуваннях доступні всім.

**Ролі за замовчуванням**

| Роль | Права |
|---|---|
| Адміністратор | усе, без обмежень (права не налаштовуються) |
| Керівник | Редагування всіх робочих розділів, Налаштування — Перегляд, Користувачі — Немає |
| Співробітник | Перегляд: Панель, Цілі, Розвиток, Звіти, Будь в темі; решта — Немає |

Свої ролі створюються кнопкою «+ Нова роль» у вкладці «Ролі та права».

## Типові дії

**Додати користувача** — вкладка «Користувачі» → «Додати»: email, пароль (≥ 6 символів), ПІБ,
співробітник із довідника (необов'язково), роль. Якщо в Supabase увімкнено підтвердження email,
людині прийде лист — увійти можна після підтвердження.

**Тимчасово закрити доступ** — відкрити користувача → вимкнути «Доступ до системи».
Неактивного користувача не пускає в панель, база теж нічого йому не віддає.

**Дати одній людині більше (або менше), ніж у її ролі** — користувач → «Індивідуальні права» →
для потрібного розділу обрати рівень замість «За роллю». Позначка • біля розділу = виняток.

**Змінити права цілої ролі** — «Ролі та права» → роль → рівні для розділів → «Зберегти роль».
Діє для всіх користувачів із цією роллю (після оновлення сторінки в них).

**Забув пароль** — користувач → «Скинути пароль»: на email прийде лист для зміни.

**Видалити користувача** — лише з рівнем «Повний» у «Користувачі та доступ». Обліковий запис
видаляється назавжди; щоб просто закрити доступ, краще вимкнути «Доступ до системи».

## Захист від помилок

- Свою роль і свій доступ змінити не можна (щоб випадково не заблокувати себе).
- База не дає прибрати **останнього активного адміністратора**.
- Системні ролі не видаляються; роль, призначену користувачам, видалити не можна.
- Хто зареєструвався сам (не через панель), отримує роль «Співробітник» і **неактивний**,
  доки адміністратор його не ввімкне.

## Що в базі (Supabase)

| Скрипт | Що робить |
|---|---|
| `insert_access_tables.sql` | таблиці `app_roles`, `app_role_perms`, `app_users`, `app_user_perms`; синхронізація з `auth.users`; функції `app_level('розділ')`, `app_is_admin()`, `app_delete_user()`. Наявні на момент запуску користувачі стали адміністраторами. |
| `secure_rls.sql` | правила RLS для робочих таблиць: читання від «Перегляд», зміни від «Редагування», видалення від «Повний». Довідники (співробітники, оргструктура) читає будь-який активний користувач. Без входу — нічого. |
| `rollback_rls.sql` | аварійний відкат RLS до режиму «будь-який залогінений може все». |

Telegram-бот працює з ключем service_role, тому ці обмеження на нього не діють.

**Новий розділ панелі** потребує: ключа в `ACC_SECTIONS` (index.html), прив'язки його таблиць
у `secure_rls.sql` і рівнів для ролей (за замовчуванням у нових розділів — «Немає», крім Адміністратора).

## Якщо щось пішло не так

- **Користувач бачить порожні розділи / помилки збереження** — перевір його роль і індивідуальні права;
  «Перегляд» не дозволяє зберігати.
- **Усі раптом без доступу** — у Supabase → SQL Editor:
  `select u.email, r.name, u.is_active from app_users u left join app_roles r on r.id = u.role_id;`
  Повернути адміністратора: `update app_users set role_id = 'admin', is_active = true where email = '…';`
- **Після `secure_rls.sql` щось зламалося** — виконай `rollback_rls.sql`, далі розбиратися спокійно.
